# 音声ファイルの管理と軽量化

中国語の音声（`audio/`）を計測し、音質を保ったままAAC 48kbps（`.m4a`）へ移行した記録です。

- 2026-09-13 計測・検証
- 2026-09-15 **実施済み**（203MB → 19.2MB、−91%）。手順と結果は「5. 実施の記録」に

## 1. 移行前の状態

### 内訳

| 種類 | 置き場所 | 件数 | 移行前 | 移行後 | 用途 |
|---|---|---:|---:|---:|---|
| 単語音声 | `audio/hskN-NNN` | 600 | 27.3MB | 4.3MB | 単語一覧・テストの「声」ボタン |
| 例文音声 | `audio/sentences/example-*` | 600 | 81.8MB | 8.3MB | 例文集・テスト後の例文再生 |
| 模試の聴解 | `audio/sentences/hskN-lX-NN` | 139 | 80.4MB | 5.6MB | 模試（自動で2回再生） |
| 聴解練習 | `audio/sentences/mock-response-*`<br>`audio/sentences/mock-dialogue-*` | 43 | 13.7MB | 1.0MB | 聴解トレーニング |
| 作文の正解（模試） | `audio/sentences/hsk3-wN-NN-answer` | 10 | — | 0.2MB | 作文を解答したあとの読み上げ（2026-09-21 追加） |
| 作文の正解（練習） | `audio/sentences/writing-bank-NNN` | 20 | — | 0.3MB | 同上・作文トレーニング（2026-09-21 追加） |
| **合計** | | **1,412** | **203MB** | **19.7MB** | |

- 形式：WAV / 44.1kHz / 16bit / モノラル（= 705kbps）
- 最大ファイル：`hsk3-l4-04.wav` 1.4MB（17秒の長い対話）
- `audio/manifest.json` 275KB（1,382件のチェックサム台帳）
- `.git` は **527MB**（初回1,339件＋その後の差し替え838件ぶんのWAVが履歴に残っているため）

### 生成のしくみ

`scripts/generate_audio.sh`（単語）と `scripts/generate_sentence_audio.sh`（例文・模試）が
macOSの `say` コマンドで生成します。`audio/manifest.json` に
「エンジン・声・無音の長さ・読み上げテキスト」から作ったチェックサムを持ち、
**内容が変わっていないファイルは再生成せず使い回します**。

## 2. 評価

### よくできている点（変える必要なし）

- チェックサム台帳による差分生成。直近の変更でも 782件中 22件だけを作り直して済んでいる
- 実ファイルと manifest が完全一致（孤児ファイル 0件、実体のない登録 0件）
- 命名規則が一貫していて、どの音声がどの画面で使われるか追える
- 内容が同一のファイルは18組だけ（例文と模試でたまたま同じ文になったケース。実害なし）

### 過剰な点

**1. サンプリングレートが実態に対して倍以上**

120ファイルを抜き取って周波数解析したところ、音のエネルギーはほぼ10kHz以下にしかありません。

| エネルギーの累積 | 中央値 | 最大 |
|---|---:|---:|
| 99.9% | 9,586Hz | 10,061Hz |
| 99.99% | 9,923Hz | 10,248Hz |
| 99.9999% | 10,301Hz | 10,650Hz |

macOSの `say` が使う音源が実質22kHz帯域のため、44.1kHz（= 22.05kHzまで記録できる）は
**情報の無い帯域に容量の半分以上を使っている**状態です。

**2. 配信サイズ**

GitHub Pages は WAV を gzip 圧縮せずそのまま配信します。模試の長い対話では1問あたり最大1.4MB、
HSK3の模試1回（聴解40問・平均737KB/問）で**約27MBのダウンロード**になります。
AAC 48kbpsなら同じ内容が約2.5MBです。

**3. リポジトリの肥大**

音声を作り直すたびに、差し替わったファイルが履歴に積み上がります（これまでの5コミットで延べ2,177件）。
現在 `.git` が527MBで、クローンのたびにこれを落とすことになります。

## 3. 検証：AAC 48kbps（.m4a）への変換

macOS標準の `afconvert` で全1,382ファイルを実際に変換し（所要約30秒、全件成功）、
元のWAVと周波数帯域ごとのエネルギーを比較しました。

### 容量

| | 変換前 | 変換後 | 圧縮率 |
|---|---:|---:|---:|
| 単語音声 | 27.3MB | 4.3MB | 6.4倍 |
| 例文・模試・聴解練習 | 175.9MB | 15.0MB | 11.8倍 |
| **合計** | **203MB** | **19.2MB** | **10.6倍（−91%）** |

単語音声の圧縮率が低いのは、0.3〜0.5秒と短くコンテナのヘッダ分の割合が大きいためです。

### 音質（元のWAVとの帯域別エネルギー差）

| ファイル | 長さ | 元 | 後 | 0-1k | 1-2k | 2-4k | 4-8k | 8-11k |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| hsk1-001（単語） | 0.42s | 41KB | 7KB | −0.1 | −0.1 | −0.2 | −0.2 | −0.2 |
| hsk3-585（単語） | 0.32s | 32KB | 6KB | −0.1 | +0.0 | −0.0 | −0.3 | −0.6 |
| example-hsk2-160（例文） | 1.56s | 134KB | 14KB | +0.0 | −0.0 | −0.1 | −0.0 | −0.2 |
| hsk2-l3-07（模試・対話） | 6.46s | 556KB | 35KB | −0.0 | −0.1 | −0.1 | −0.2 | −0.2 |
| mock-dialogue-003 | 5.57s | 479KB | 30KB | +0.0 | −0.1 | −0.1 | −0.1 | −0.2 |
| hsk3-l4-04（最長） | 17.07s | 1470KB | 102KB | −0.0 | −0.1 | −0.1 | −0.1 | −0.1 |

単位はdB。**全帯域で0.6dB以内**に収まり、再生時間も完全に一致しました。人の耳で違いは分かりません。

### 他の設定との比較（hsk3-l4-01・1.3MB で測定）

44.1kHzのまま変換しても、22.05kHzに落としてから変換しても、サイズ・音質の差は2%以内でした。
下表は後者の値です。

| 設定 | サイズ | 圧縮率 | 判定 |
|---|---:|---:|---|
| 22.05kHzのWAVに変換 | 666KB | 2.0倍 | 無劣化だが圧縮率が低い |
| AAC 24kbps（22.05kHz） | 46KB | 28.5倍 | 6〜11kHzが−4.8dB以上落ちる。不可 |
| AAC 32kbps | 62KB | 21.3倍 | 8〜11kHzが−2.4dB。子音（s/sh/x/q）が鈍る恐れ |
| **AAC 48kbps** | **89KB** | **14.8倍** | **全帯域0.6dB以内。推奨** |
| AAC 64kbps | 116KB | 11.4倍 | 48kbpsと差がない |

中国語は s/sh/x/q など高めの子音の聞き分けが重要なので、8〜11kHzが落ちない48kbpsを採ります。

### 互換性

- `.m4a`（AAC-LC）は Safari・iOS Safari・Chrome・Firefox・Edge のすべてで再生可能
- 再生速度の変更（0.85× / 1.0× / 1.15×）や `preservesPitch` も従来どおり動作
- 音声が見つからない場合はブラウザの読み上げに切り替わる作りなので、移行漏れがあっても無音にはならない（ただし音質は落ちる）

### チェックサムの扱い

`audio/manifest.json` のチェックサムは**読み上げ内容（声・テキスト・無音の長さ）を表すもの**で、
配信形式は含めません。形式は manifest の見出しに `format` / `codec` / `bitrate` として記録します。
このため今回の移行では既存のチェックサムをそのまま使え、`say` での作り直しは1件も発生しませんでした。
ビットレートを変えたいときは `say` を回さずに `afconvert` で変換し直すのが正しい手順です。

### リポジトリ履歴について

変換後も `.git` は527MBのままです（過去のWAVが履歴に残るため）。
`git filter-repo` で過去の音声を履歴から削除すればクローンは**約30MBまで縮みます**が、
履歴の書き換えと force push が必要で、元には戻せません。
個人リポジトリで他に誰もクローンしていないなら実害は小さい、という判断です。

## 5. 実施の記録と再現方法

### 移行の手順（実際に行ったもの）

```sh
# 1. 既存のWAVをすべて変換（1,382件・約30秒）
for f in audio/*.wav audio/sentences/*.wav; do
  afconvert -f m4af -d aac -b 48000 "$f" "${f%.wav}.m4a"
done

# 2. manifest の見出しと file 欄を .m4a に更新（チェックサムは据え置き）
# 3. 生成スクリプトが作り直さないことを確認
node scripts/generate_sentence_audio.mjs   # → 完了: 782件（生成0 / 再利用782）
zsh scripts/generate_audio.sh              # → 音声生成完了: 600 語

# 4. 旧WAVを削除
rm audio/*.wav audio/sentences/*.wav
```

### 移行後の確認（Chromiumで実測）

| ファイル | 長さ | サイズ | 読み込み | 再生 |
|---|---:|---:|---|---|
| `hsk1-001.m4a`（単語） | 0.49秒 | 7KB | ✓ | ✓ |
| `example-hsk2-160.m4a`（例文） | 1.63秒 | 14KB | ✓ | ✓ |
| `hsk3-l4-04.m4a`（最長の対話） | 17.14秒 | 102KB | ✓ | ✓ |
| `mock-dialogue-003.m4a`（聴解練習） | 5.62秒 | 30KB | ✓ | ✓ |

`canPlayType('audio/mp4; codecs="mp4a.40.2"')` は `probably`。
アプリ側のコードに `.wav` の参照が残っていないことも確認済みです。

### 計測の再現方法

```sh
# 容量
du -sh audio

# 形式
afinfo audio/sentences/hsk3-l4-01.m4a

# ビットレートを変えたいとき（say は回さず、既存の音声を変換し直す）
HSK_SENTENCE_AUDIO_BITRATE=64000 node scripts/generate_sentence_audio.mjs   # ※要 HSK_SENTENCE_AUDIO_FORCE=1

# 音質の比較（.m4a を WAV に戻して帯域ごとのエネルギー差を測る）
afconvert -f WAVE -d LEI16@44100 audio/sentences/hsk3-l4-04.m4a /tmp/check.wav
```

周波数解析は Python（wave + numpy）で、ハニング窓1024点のスペクトログラムを
帯域ごとに積算して元ファイルと比較しています。
